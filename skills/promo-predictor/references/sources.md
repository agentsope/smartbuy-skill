## 2. promo-predictor 专用查询模板

### 2-1. 抓"历史价格 timeline"

**查询模板**(必带年份范围):

```
"{商品名} 京东 价格 2024 2025"
"{商品名} 双11 历史最低"
"{商品名} 618 历史价"
"{商品名} 历史价格走势"
```

**目标**:拿到 **3-5 个真实时点**:
- 上次 618(2024-06 或 2025-06)
- 上次双 11(2024-11 或 2025-11)
- 上次国庆/38/黑五(可选,加分项)
- 当前价

### 2-2. 抓"末代换代信号"(关键)

如果商品已上市 > 2 年,**必查**有没有新一代发布:

```
"{品牌} {型号} 下一代 发布"
"{品牌} {型号} 后续 升级"
"{商品名} 停产 清库存"
```

**作用**:识别"末代换代风险"。
**实例**:promo-predictor 跑罗技 MX Master 3S 必须先查 MX Master 4 状态 → 拿到"2025-09 已发布"信号 → 影响预测(可能限量秒杀更狠 / 也可能直接停产)。

### 2-3. 抓"国补政策动态"

国补 2024-2026 政策动态调整,大促前可能变化:

```
"国补 2026 政策 {品类}"
"国补 退坡 大促"
"国补 资格 {省份}"
```

## 3. 数据时点抓取标准

每个数据时点必须包含:

| 字段 | 说明 |
|---|---|
| **日期** | 精确到日(如 2025-11-11) |
| **价格** | 数字 + 是否含国补 / Plus / 凑券 |
| **平台** | 京东自营 / 天猫官旗 / 拼多多百亿补贴 等 |
| **来源** | 报道域名 + URL |
| **限量否** | "限量 200 台" 这种**不能算常规大促价**(§judgment-rules-3c §7-2 规则) |

---

## 4. 数据点不足时的退路

**< 3 个真实时点** → **不预测**,走 `data-insufficient-fallback` 模式:

```text
"{商品} 我能拿到的历史时点有限(只有 N 个,需 ≥ 3 个才能预测)。
不预测,建议用 `price-detective` 看当前折扣率,作为替代信号。
等过去 1 个大促后(收集到第 3 个真实时点),再来问我。"
```

**例外**:Apple/3C 新品上市 < 6 个月,**预测都不准**(没经历过大促周期),直接退路。

---

## 5. 数据互相矛盾的处理

WebSearch 拿到两个相互矛盾的历史时点 —— 比如某文章说"双 11 ¥299",另一文章说"双 11 ¥348":

**判断步骤**:
1. **看是否限量秒杀**:¥299 可能是"限量 200 台" 这种,不能算常规大促底
2. **看时间**:近期报道优先(2025 vs 2024)
3. **看来源权威性**:IT之家 / 中关村在线 / 新浪科技 = 高;社交媒体晒单 = 低
4. **看渠道**:京东自营 vs 拼多多百亿补贴 = 不同价格体系,分别记录

输出时**并列展示矛盾的数据**,让用户判断:

```text
"近 1 年大促底:
- 2025-11.11 IT之家报道 ¥348(常规大促价,全天可买)
- 2024-06 新浪科技报道 ¥299(限量 200 台 20:00 秒杀,**不能作为常规预测锚点**)
取 ¥348 作预测基础。"
```
