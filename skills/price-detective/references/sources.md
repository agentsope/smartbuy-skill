## 2. WebSearch — 主源用法

- 当前价 + 国补:`"{商品名} 京东自营 价格 国补 2026"`
- 历史最低 + 大促:`"{商品名} 历史最低价 618 双11"`
- 真假优惠 / 渠道:`"{商品名} 港版 国行 差价"` / `"{商品名} 教育版 价格"`
- 大促预测:`"{商品名} 双11 价格 历史"`

**最稳的快照源**(科技媒体,SSR 友好):

| 域名 | 内容 | 价值 |
|---|---|---|
| `ithome.com` | IT之家 — 3C 大促报道,**精确到日期 + 限量数 + 国补幅度** | ⭐⭐⭐ 历史价时间戳最准 |
| `m.zol.com.cn` / `nb.zol.com.cn` / `news.zol.com.cn` | 中关村在线 — 当前活动价 + 历史活动汇总 | ⭐⭐⭐ 当前价最及时 |

### 2.5-2. 失效切换规则

WebSearch 时如果**主源全部 0 命中**(返回都是英文 / 不相关结果),立刻按这个顺序重试:

1. **改关键词搜法**:`"{商品} 价格 历史"` → `"{商品} 测评 大促"` → `"{商品} 京东 多少钱"`
2. **加备份源 site 限定**:`site:36kr.com {商品}` / `site:leitech.cn {商品}`
3. **3 次切换仍 0 命中**:走"搞不定退路场景表"(§4-6)— 让用户去**慢慢买 / 购物党 App** 自己查,**不要硬凑数据**

### 2.5-3. 主源失效预警

每次 WebSearch 时,**留意**这些信号 — 主源开始失效的早期迹象:

- 主源域名跳转到完全不同站点
- 返回结果全是几年前旧文(SEO 降权信号)
- HTTPS 证书错误 / 502 / 403 反爬
- 返回首页而非搜索结果(SEO penalty)

任一信号出现 → **在输出末尾标注**:"⚠️ 主源 X 似乎失效,本次结果来自备份源 Y,数据时效可能延后",并提交 issue 让维护者更新源清单。

## 3. 慢慢买 — 辅源用法

**正确入口**:`https://s.manmanbuy.com/default.aspx?key={URL_encoded_keyword}`
**错误入口**(别用):
- `https://www.manmanbuy.com/Default.aspx?key=` — 首页 JS 渲染,WebFetch 看不到
- `https://cu.manmanbuy.com/dingyue/brand/X/ctY` — 302 跳验证页

**命中率实测**(基于 e2e 001/002/003):

| 商品/品类 | 慢慢买搜索命中 |
|---|---|
| MacBook Pro 14 M5 | ✓ 8 条命中 + 历史标签 |
| MacBook Pro 14 M5 Max | ✓ 多个配置 + 已结束历史 |
| iPhone 17 | ✓(从首页热卖榜看到) |
| 罗技 MX Master 3S | ✗ 不命中 |
| 雅诗兰黛小棕瓶(任何变体) | ✗ 不命中 |

**经验法则**:
- Apple / iPhone / iPad / 顶级品牌型号 → 大概率命中,优先取**历史标签**(历史新低 / 低于60天均价 / 低于618)
- 主流 3C(罗技/索尼/戴尔/小米外设等)→ 命中率 30-50%,搜不到很常见 → **直接走 WebSearch**
- 美妆/服饰/食品/日用 → 几乎不命中 → 走 `non-3c-fallback` 模式

**命中后,优先抓的字段**:
1. **历史价标签**:历史新低 / 低于60天均价 / 低于618 / 低于双11(WebSearch 拿不到这种结构化标签)
2. **多平台横评**:慢慢买的搜索结果一行就给你平台 + 价 + 状态(在售/已结束)
3. **赠品 / 国补 标注**:慢慢买会把"含国补"、"满 N 减 M"标在标题里

## 4. **比价网商品页 URL — 主动给用户**

**核心修正**(来自真实用户反馈 + 2026-05-29 实测):比价网的真正价值**不是让我们 WebFetch 拉曲线**(拿不到,JS 异步),而是**给用户一个能在浏览器看完整曲线的 URL**。**Skill 的标准输出应主动包含 1-2 个比价网商品页链接**,让用户点过去看曲线/360 天历史/价格预警。

### 4-1. 慢慢买 — URL 模板(实测可访问,2026-05-29)

| 用途 | URL 模板 | 实测 | 给用户看什么 |
|---|---|---|---|
| **关键词维度走势页** | `https://cu.manmanbuy.com/dingyue/keyword/{关键词}/2` | ✓ 200 加载(不是验证页) | 该关键词下所有 SKU 的折扣 + 历史价格 |
| **SKU 维度详情页** | `https://cu.manmanbuy.com/discuxiao_{商品ID}.aspx` | ✓ 200 加载 | 单 SKU 完整价格曲线 + 历史最低 + 平台横评 |
| **品类折扣页** | `https://zhekou.manmanbuy.com/searchnew.aspx?key={关键词}&infotype=2` | ✓ 200 加载 | 该关键词的实时折扣推荐 |
| **历史价工具页**(用户贴 URL) | `https://tool.manmanbuy.com/historylowest.aspx` | ✓ 加载 | 用户贴商品 URL → 看曲线 |
| **手机版工具页** | `https://tool.manmanbuy.com/m/history.aspx` | ✓ 加载 | 同上,移动端友好 |

### 4-2. 购物党 — URL 模板

| 用途 | URL 模板 |
|---|---|
| **商品历史价工具** | `https://www.gwdang.com/`(浏览器 / App 内输入商品 URL) |
| **App 下载** | `https://apps.apple.com/cn/app/{...}` / `https://app.mi.com/...` |
| **AI 价格预测** | 购物党 App 内置(浏览器版没有) |

> ⚠️ 购物党的网页搜索 / 商品查询路径 **WebFetch 仍触发反爬**,但**给用户 App 链接是 OK 的**。

### 4-3. 历史价格查询(lsjgcx) — URL 模板

| 用途 | URL 模板 | 实测 |
|---|---|---|
| **工具首页** | `https://www.lsjgcx.com/` | ✓ |
| **GET 查询(用户贴商品 URL)** | `https://p.zwjhl.com/price.aspx?url={URL_encoded_商品链接}` | ✓ 页面加载,但价格数据 JS 异步 |

### 4-4. **标准 Skill 输出格式**

每次 `judge / timing / debunk` 输出 **必须包含**:

```
完整曲线 / 360 天历史 / 价格预警 → 点这里看:
- 慢慢买:https://cu.manmanbuy.com/dingyue/keyword/{商品关键词}/2
- 慢慢买工具:https://tool.manmanbuy.com/historylowest.aspx(贴你的京东 URL)
- 购物党 App:浏览器搜"购物党" 装 App,贴商品链接看曲线 + 价格预警
```

**为什么必须主动给**:
- WebFetch 拿不到曲线(JS 异步限制)
- 对话不能渲染图表
- 让用户"自己截图发我" = 把工作推给用户(差体验)
- 主动给 URL = 用户一键看完整数据(好体验 + 不需要我们解读截图)

## 4-6. **搞不定时的退路场景表(用户反馈强化版)**

**核心**:遇到下列任一搞不定的场景,**默认给用户对应 URL**,而不是说"我没办法"。

| 搞不定场景 | 触发条件 | 给用户的 URL / 工具 |
|---|---|---|
| **慢慢买搜不到** | `s.manmanbuy.com` 搜索返回 0 结果 | 给 `cu.manmanbuy.com/dingyue/keyword/{X}/2` + 慢慢买 App 让用户在 App 里搜 |
| **WebFetch 反爬** | gwdang / cu.manmanbuy 等返回验证页 | 给购物党 App 链接 + 慢慢买 App |
| **数据冲突**(两个源对不上)| WebSearch A 源 ¥X / 慢慢买 ¥Y 差 > 10% | 让用户去**慢慢买工具页**贴自己的 URL 自己核 |
| **没历史曲线**(新品)| 历史时点 < 3 个 | 给慢慢买 App + 购物党 App 让用户**设价格预警**(等够数据再问) |
| **用户给的链接解析失败** | 淘宝短链 e.tb.cn / 京东短链 m.jd.com | 让用户贴标准 PC 链接;**同时给慢慢买工具页**作备用 |
| **品类不在 覆盖** | 服饰 / 食品 / 国货护肤 / 香水 / 彩妆 / 球鞋 | 推**慢慢买 App + 什么值得买 + 得物**(球鞋专用)+ Extrabux(海淘) |
| **大促预测置信度低** | promo-predictor 数据点 < 3 个 | 给购物党 App(AI 预测 + 价格预警最强) |
| **用户问短期价格**(明天 / 一周内)| "明天会降价吗" | **拒绝预测** + 推购物党 App 设价格预警 |
| **跨平台数据不全**(只有京东没拼多多)| WebSearch 没拿到某平台 | 让用户自己开 PDD 百亿补贴 + 给慢慢买工具页对照 |
| **用户问海淘 vs 国内**(美妆/3C) | 涉及海淘渠道差 | 给 Extrabux 攻略 + Dealmoon 北美省钱快报 + 别样 |
| **二手 / 翻新 / 官换**(用户问"靠不靠谱") | 第三方店深度低价 | 推**得物**(球鞋 / 数码二级)+ 拼多多百亿补贴对照 |

**为什么这么设计**(产品哲学):
1. **承认能力边界 > 假装无所不能**
2. **比价网比我们的对话有时更直接**(他们做了多年,数据深)
3. **用户体验:给我链接 > 让我截图发你**
4. **诚实:我们抓不到的,有现成工具能拿到**

## 5. WebFetch 抓不到的部分(诚实标注)

**WebFetch 拿不到的**(JS 异步 / 反爬 / 需登录):
- 慢慢买 / 购物党 / lsjgcx 的**具体价格曲线数据**
- 拼多多 / 抖音 / 淘宝 的**实时价格**
- 京东 PLUS 价 / 国补叠加后的实付(需登录)

**WebFetch 能拿到的**(SSR / 公开):
- 慢慢买 / 购物党 的**商品页框架**(能给用户跳转 URL)
- 科技媒体促销报道(IT之家 / 新浪科技 / 中关村 / 值值值)
- 苹果 / 京东 / 天猫 公开页面的**部分元数据**
- WebSearch 综合的**报道时点价格**

**Skill 不空跑**:**用户提到曲线 / 历史 / 走势** → 主动给 §4 的 URL,而不是说"我没法看曲线"。

## 6. 数据源策略总结

**对话内能解决的**(我们做):
- 一句判断 / 跨平台横评 / 历史关键时点 / 假优惠戳穿 / 决策框架(美妆)

**必须给用户外部 URL 的**(我们生成 URL,用户去看):
- 完整价格曲线
- 360 天 / 60 天均价 详细数据
- 实时价格预警 / 盯价提醒
- 多 SKU 多颜色对比详细列表

**两者结合 = 完整购物决策**:Skill 给思考,比价网给数据深度。

## 6. 输入残缺时的搜索退路

| 用户给的 | 我先抓什么 |
|---|---|
| 标准 PC 链接 | WebFetch 链接 → 拿品名/配置 → WebSearch "{品名} 京东 国补" |
| 短链 | 请用户贴 PC 链接;**同时**用商品标题(如果用户描述了)走 WebSearch |
| 商品名 + 描述(无链接) | WebSearch "{名字} 京东自营 价格" + "{名字} 历史最低 618" |
| 商品截图(只看到价) | 提取截图里的品名/配置 → WebSearch;只看价 → 没法判断,要补品名 |
| 只说品类("帮我买个鼠标") | **拒绝**:这不是 price-detective 的事,告诉用户先选定一个具体商品再来 |

## 7. 数据时效性自检

WebSearch 拿到的内容**多数有日期**,要核:
- 价格类**最近 1 个月**的报道 → 可作"当前价"参考
- 价格类**1-12 个月**的报道 → 作"历史价"参考,**标原文日期**
- 价格类**> 12 个月**的报道 → 仅作"上市原价"或"历史最低"对照,**不能拿来说"现在多少"**

如果搜到的全部是旧报道(没有近 3 个月的),要明说:"近期价格没拿到独立数据,这是 X 月前的报道价"。
